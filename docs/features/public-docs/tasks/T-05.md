# T-05: Alfred section

- **Roadmap:** ../ROADMAP.md · **Phase:** 2 · **Repo:** nesolva/docs · **Base branch:** release/public-docs-p2 (PR targets it, not main) · **Branch:** docs/alfred
- **Depends on:** T-01 merged · **Model:** sonnet

## Goal
An operator understands what Alfred does and can carry out their daily work alone:
- sign in;
- follow tasks;
- upload an invoice;
- review and finalize a task;
- search invoices;
- work with purchase orders;
- fix the common errors.

## Scope
- Files/areas: `es/alfred/*.mdx`, eight stubs from T-01.
- Source: SOURCE-FACTS.md, section C, plus "Billing mailbox" and the "Operador" role from section B.
- Out of scope: `docs.json`, and any detail of how Alfred extracts or validates data internally.

## Contract
- Roadmap Decisions and Contracts.
- `alfred/introduccion`: what it does, in product terms. For the operator and the administrator to have ready before
  starting:
  - the organization has Alfred enabled (ask Nesolva);
  - the admin assigns the **Operador** role;
  - the admin connects the billing mailbox (link to `/es/ailita/admin/casilla-de-facturacion`).
- `alfred/panel-y-tareas`: what each status means (Pendiente, En proceso, Revisión manual, Finalizada, Falló) and
  what the operator does with each one.
- `alfred/revisar-tarea`: claim the task, edit fields, finalize, correct a finalized task, and the state history.
  Explain field confidence in user terms: it shows how sure Alfred is, and low confidence calls for a careful
  look. Nothing about models or how the confidence is calculated.
- `alfred/ordenes-de-compra`: start with a `<Note>` saying that this module only appears if Nesolva enabled it.
- `alfred/problemas`: every message in table C, plus "allow pop-ups" with generic steps for Chrome, Edge and Safari.
- Don't publish the maximum upload size: say "if the file is too large, split it or compress it".
