## Goal
An operator understands what Alfred does and can carry out their daily work alone:
- sign in;
- follow tasks;
- upload an invoice;
- review and finalize a task;
- search invoices;
- work with purchase orders;
- fix the common errors.

## Scope
- Files/areas: `es/alfred/*.mdx`, eight stubs from T-01.
- Source: SOURCE-FACTS.md, section C, plus "Billing mailbox" and the "Operador" role from section B.
- Out of scope: `docs.json`, and any detail of how Alfred extracts or validates data internally.

## Contract
- Roadmap Decisions and Contracts.
- `alfred/introduccion`: what it does, in product terms. For the operator and the administrator to have ready before
  starting:
  - the organization has Alfred enabled (ask Nesolva);
  - the admin assigns the **Operador** role;
  - the admin connects the billing mailbox (link to `/es/ailita/admin/casilla-de-facturacion`).

- `alfred/problemas`: every message in table C, plus "allow pop-ups" with generic steps for Chrome, Edge and Safari.

### Spec problem: the content check blocks the status "Pendiente"
`scripts/check-public-content.sh` runs `grep -i`, so the placeholder pattern `\bPENDIENTE\b` also matches the real
Alfred status **Pendiente**, which the contract requires in `panel-y-tareas.mdx` (and which Ailita Backoffice's
access-recovery statuses also use, so T-03 will hit the same). The two matches are in `es/alfred/panel-y-tareas.mdx`.
I did not work around it with odd spelling. Suggested fix, outside this task's scope: make that one pattern
case-sensitive (or drop it) in the script.

The same script also flags `botón` (`\bbots?\b`) and `método` (`\bTODO\b`) when it runs under the default C locale
(`LANG=""`). Under `LC_ALL=en_US.UTF-8` only `PENDIENTE` fails. Worth setting the locale in the script or in CI.
